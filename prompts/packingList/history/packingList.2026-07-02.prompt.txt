## Case 1: standard line item layout
- For standard, the line item convey only single line item entity

## Case 2: consolidated line item layout
- For consolidated layout, the line item looks like a single row but it actually consolidates multiple items.
- For products like shoes, clothes, etc, it is quite typical to see a single line item with multiple size columns
  where each columns carry info like QTY, QTY/carton, etc.
- For example, some line item may has columns:
  Carton num start, Carton num end, Carton QTY, Size-S, Size-M, Size-L, .... Total QTY
  In that case, if there are multiple QTYs in the size columns, it is a consolidated line item layout.
- In that consolidated case, you should:
  - yield multiple item entities to prevent data loss

<packingListLayout>
## overview
- Among the doc pages, you should only look at pages that they contain packing list content.
- In practice, it is very common that there are multiple packing lists in a single doc.
- Thus, it is here to define a unit of a packing list by one of the different layout below:

## Packing list layouts
- 'standard' (standard layout)
  - This refers to standard and common packing list layout that it has a explicit packing list number.
  - Explicit means it has explicit label like 'packing# xxxx', 'packing list: yyyy', etc. 
  - If there is NO explicit label to indicate packing list number, do NOT infer from other labels, e.g. reference number, as packing list number.
  - In this case, packing list are defined by unique packing list number, e.g.
    P.1-3 PL-00011, P.4 PL-00012, P.5-10 PL-00013, etc
  - In this example, the packing lists: 
    - packing list #1 -> P.1-3  PL-00011 (this is the first packing list)
    - packing list #2 -> P.4    PL-00012
    - packing list #3 -> P.5-10 PL-00013
- 'sharedPackingListNum' (layout using shared packing list number with multiple PO number)
  - The is one of the edge case that some suppliers may issue a non-standard layout that 
    the pages has explicit packing list number but the same packing list number is re-used/shared with different PO numbers.
  - For example:
    P.1-2 PL-00021 PO#0010, P.5-6 PL-00021 PO# 0011, P.21-30 PL-00022 PO# 0013, etc
  - In this example, the packing lists:
    - packing list #1 -> P.1-2 PL-00021 PO#0010, P.5-6 PL-00021 PO# 0011 (this is the first packing list)
    - packing list #2 -> P.21-30 PL-00022 PO# 0013
- 'sharedInvoiceNum' (layout with multiple occurrences of invoice number, no explicit packing list number)
  - The is another edge case that some suppliers may issue a non-standard layout that
    the pages has no explicit packing list number but the same invoice number is re-used/shared in multiple pages.
  - For example:
    P.1-2 INV#1011 PO#9002, P.5-6 INV#1011 PO#9002, P.21-30 INV#1012 PO#9003, etc
  - In this example
    - packing list #1 -> P.1-2 INV#1011 PO#9002, P.5-6 INV#1011 PO#9002 (this is the first packing list as it shares the same invoice number '1011')
    - packing list #2 -> P.21-30 INV#1012 PO#9003
- 'unknown' (unknown layout)
  - This refers to unknown layout and thus it cannot determine the correct units of packing list for entity extraction
  - In this case, it should be considered as error
</packingListLayout>
